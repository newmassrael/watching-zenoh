# 이 세션에 대하여

헤드리스 러너(scripts/round-runner.sh)가 이 프롬프트를 **매번 새 세션**에
넣는다. 앞 라운드의 대화는 없다. 상태는 atomic ledger 와 agent memory 가
나른다 — 그것이 이 워크스페이스의 설계다.

`load` 는 CLAUDE.md 의 auto-kickoff 5단계를 뜻한다. -p 모드에서는 트리거가
자동 발동하지 않으므로 직접 수행한다: concept 6종 -> validate_workspace
베이스라인 -> 최신 changelog entry 의 carry_forward -> git status/log ->
**살아 있는 부채 등록부**(agent memory 의 project_open_debt_register_* 중
LIVE 표시된 최신 것). 등록부의 「착수 순서」에서 **정확히 한 건**만 고른다.

# GOAL

**등록된 부채가 0 이 될 때까지.** 한 라운드는 한 건이다. 남은 건수는 매
라운드 등록부에 갱신되고, 그 수가 0 이 되면 러너가 멈춘다.

# 이 리포의 규칙 (어기면 라운드가 무효다)

- **실측으로 시작한다.** 등록부의 I 표시는 측정이 아니라 추정이다. 인용하지
  말고 다시 재라 — 표본 10건 중 7건이 틀렸던 전례가 있다.
- **falsify 프로브를 돌린다.** 새 게이트마다 그것이 지키는 동작을 일부러
  깨서 **그 테스트만** red 인지 본다. **프로브가 통과하면 「코드가 맞다」가
  아니라 「테스트가 틀렸다」**로 읽어라 — 한 테스트에 결과를 혼자서도 만드는
  원인이 둘이면 어느 쪽도 게이트하지 못한다.
- **게이트 완화로 닫지 마라.** 임계값을 낮춰 만든 green 은 상환이 아니다.
- **셸 파일을 추가했으면 그 파일만** `shellcheck -S info <file>` 로 건다.
  Layer 0 전체는 로컬에서 상시 red 다 (베이스라인 = SC2317 3323, 그 외 0).
- **워크스페이스 전체 빌드는 안 된다** -> `-p <crate> --all-targets`.
- run-ci.sh 는 리포 루트에서. **빈 출력을 통과로 읽지 마라 — 파일로 받아라.**
- 한 명령에서 cd 하면 그 cwd 가 다음 호출까지 유지된다. 절대경로로 시작해라.
- 커밋은 COMMIT_FORMAT.md (불릿 1~3, 각 줄 72바이트 이하, 들여쓴 연속 줄 금지,
  Co-Authored-By 금지, 이모지 금지). **원장은 자기 커밋에 따로 담는다.**
- push 는 `git push origin main` (맨 `git push` 는 upstream 이 없어 실패한다).
  훅 4개가 전부 통과해야 나간다. **--no-verify / --force 는 금지다.**
- push 했으면 **호스티드를 job 단위로 읽는다.** 끝날 때까지 기다린다.
  ⛔ **`gh run list` 의 맨 위를 집지 마라.** 방금 민 커밋의 SHA 로 특정해라 —
  `gh run list --json databaseId,headSha,status,conclusion` 에서 `headSha` 가
  그 커밋인 것. 앞 라운드의 실행이나 남의 실행이 위에 있을 수 있다.
  (ci.yml 의 concurrency 가 ref 당 최신 하나만 남기지만, 그건 낡은 실행을
  «취소»하는 것이지 네가 옳은 것을 «고르는» 일을 대신해 주지 않는다.
  cancelled 는 green 이 아니다 — 네 커밋의 실행이 cancelled 로 끝났다면
  그 사이에 누가 또 밀었다는 뜻이니 STOP 이다.)

# 라운드를 닫으면 `.round/status` 를 쓴다 — 러너의 정지 조건이다

첫 줄은 정확히 다음 셋 중 하나다.

    CONTINUE
    DONE: 등록 부채 0
    STOP: <한 줄 이유>

**CONTINUE** — 아래가 전부 참일 때만.
- 호스티드 15 job 전부 green.
- 고른 항목을 실제로 닫았고 등록부·원장·MEMORY.md 에 반영했다.
- 남은 부채가 아직 있고, 다음 항목이 사람의 결정을 요구하지 않는다.

**DONE** — 등록부에 열린 항목이 하나도 없고 호스티드가 green 일 때.

**STOP** — 하나라도 해당되면.
- 호스티드가 red. 이유에 run id 와 job 이름을 적는다.
- 실측이 등록부의 서술을 반증했다 (등록부를 고치고 사람에게 알린다).
- falsify 프로브가 통과하는데 테스트를 고쳐도 red 가 안 난다.
- 항목이 사람의 결정을 요구한다 (예: 그것이 이 리포의 부채인지 자체가 미정).
- 빌드/링크 에러를 라운드 안에 해소하지 못했다.
- `.git/wz-nda-terms.txt` 가 `!acknowledged-empty` 한 줄뿐이다 — 무인 push 의
  유일한 실질 가드가 비어 있다. 그 사실을 이유에 적고 멈춘다.
- 무엇을 해야 할지 확신이 없다. **추측해서 진행하느니 멈춰라.**

둘째 줄부터 사람이 읽을 3~10줄 요약: 무엇을 쟀고, 무엇을 닫았고, 다음은 무엇인지.
