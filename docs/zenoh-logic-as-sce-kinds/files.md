# Which slice reads each file

Every tracked `.rs` file under `src/` of a crate that `crates.md` says a slice
reads is either cited by a row of one of that crate's slices or left out with a
reason. `scripts/lib/logic_census_coverage_gate.py` holds this table to the
tracked tree: a file with no row, a row naming no tracked file, a slice that
`crates.md` does not name for the file's crate, a slice none of whose rows cites
the file, and an exclusion without a reason are each a failure.

A row of a slice cites a file by its full path, by a cited directory
`crates/<crate>/src/<dir>/` that holds it, or by its path below `src/` or a tail
of it at a `/` (`lib.rs:120`, `rt/router_forward.rs:610`), the short form S1 to
S6 use. A scope paragraph that names a whole `src/` cites no file. The short
form cannot tell two crates' `lib.rs` apart within one slice; the gate accepts it
as the slice's word.

The `Where` column holds the slices (`S1, S10`), or `excluded: <kind>`, where the
kind is `test` (test-only code or fixtures), `generated` (written by a
generator) or `scope` (a slice's scope paragraph leaves it out; the reason names
that slice). A test-only file by its name (`tests.rs`, `*_tests.rs`, a `tests/`
directory) is excluded as `test` with that reason.
