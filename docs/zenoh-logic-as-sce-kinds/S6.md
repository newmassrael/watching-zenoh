# Census slice S6: zenoh API family and server services

Scope: `crates/wz-zenoh*` (15 crates, the upstream-1.10.2-compatible surface) and the server
crates `wz-storage`, `wz-admin`, `wz-ext-pubsub`, `wz-auth`, `wz-access-control`.
Production lines are counted with `#[cfg(test)]` items, `tests.rs` files and `tests/` /
`benches/` / `examples/` directories removed (89,494 lines in all). Line counts per row are
approximate where a row is part of a file.

SCE references used throughout (read from `origin/main` of scxml-core-engine):
- catalog = `kind-catalog.json` (the yardstick);
- FORGE = `SCE_FORGE.md` (§4.12 algorithm: byte-buffer-build, `list<T>` of fixed-width
  elements only, records whose text fields allow only copy and `===`, lists of records,
  "an algorithm whose signature takes or returns a list cannot be called from another
  algorithm"; §3.4.2 wrapping ops; §4.3 lookup; §5.6 policy as data);
- SUBSET = `docs/SCE_ACCEPTED_SUBSET.md` (line ~7989: "a `sce-static` statechart has no
  variable of that kind" [bounded-collection]; line ~4728: a statechart variable may be
  `list<record:R>[N]`);
- RFC = `docs/rfc-sce-protocol-synthesis.md` (§5.H tree kinds deferred; §5.I `sce:extern`
  whitelist = atomics, fences, cache maintenance, IRQ only; §5.L bounded-collection with
  `index-by`);
- STD = SCE `stdlib/` (precedents: `hash/murmur3_32`, `merge/merkle_insert|merkle_diff`,
  `merge/lww_write`, `merge/hlc_compare`, `acl/acl_membership|acl_granted`,
  `mesh/retry_next_backoff`).

Key finding up front: `sources/algorithms/keyexpr_includes.scxml` and `keyexpr_intersect.scxml`
are uint32-id-equality placeholders (`broader_id === narrower_id`); nothing in `out/` is
generated from them and no Rust calls them. The wildcard matching wz actually runs exists
twice by hand: `wz_session_core::keyexpr_match` (used by storage, admin, ACL in this slice)
and the independent dynamic programs of `wz-zenoh-keyexpr` (used by the `zenoh` API). There is
no class-A row in this slice.

## Summary

- **Lines by class.** Production lines in the rows add up to 89,160 (95 rows; rows 94 and 95,
  601 lines, were added on 2026-11-20 by the file-level coverage pass). The slice measures
  89,494; the rest is rounding in rows that cover part of a file.
  - A = 0
  - K = 16,930, of which 9,176 is the hand copy of upstream `zenoh-codec` (row 12). Without
    it, K = 7,754.
  - G = 25,946
  - S = 6,829
  - D = 5,133
  - X = 34,322
- **Gaps found** (one row may carry several codes):
  - **R** (new code) — no text operations on data. 15 rows: 4, 5, 9, 10, 25, 47, 53, 54, 68,
    74, 75, 80, 85, 90, 92. A value made of several texts has no form: `list<T>` refuses
    string elements, and a record's text has only copy and `===` (FORGE §4.12). So no
    algorithm can produce texts from input bytes, and none can run a keyexpr match on a
    keyexpr held in a rule or registry table. This is what blocks the ACL decision (row 92),
    although its deny-first logic is exactly what `sce:std/acl/acl_granted` already
    expresses.
  - **M** — 18 rows: 10, 14, 24, 29, 37, 39, 41, 52–57, 66, 67, 69, 83, 90. The maps are keyed
    by keyexpr, zid or name, and upstream does not bound their occupancy. `bounded-collection`
    with `index-by` covers them only when a capacity is declared, and only when the host drives
    the collection: a `sce-static` statechart cannot hold one (SUBSET ~7989).
  - **T** — 7 rows: 4, 5, 6, 22, 36, 37, 69. The KeTree trie, the JSON5 config tree and
    backtracking keyexpr-format parsing. RFC §5.H is still deferred.
  - **H** — 8 rows: 9, 28, 39, 45, 64, 66, 79, 83. Samples and payloads of unbounded size held
    in channels, caches, reorder buffers and stores.
  - **A** — 5 rows (24, 40, 41, 46, 84), plus `BlockOn` inside row 16. Many in-flight gets,
    each ended when its last leg is dropped or when it is cancelled, and an open set of
    one-shot and periodic timers.
  - **F** — 5 rows: 22, 25, 36, 69, 74. JSON5 and RFC 3339 parsing. The `sce:extern` whitelist
    (RFC §5.I) covers atomics, fences, cache maintenance and IRQ only.
  - **C** — 5 rows: 6, 14, 17, 28, 46. Atomics in cross-process SHM headers, Arc-shared tree
    nodes and buffers, and cancellation.
  - **P** — row 72, a caveat on a K row: a generated per-leg algorithm loses the query
    preparation that was measured (one quarter of the instructions of an admin GET).
- **Deliberate fixes a migration must carry:** rows 1, 2, 36, 37, 39, 42, 52, 54, 55, 59, 60,
  66, 69, 71, 72, 73, 75, 80, 83, 84, 92.
- **Doubts and findings outside the classes:**
  1. `sources/algorithms/keyexpr_includes.scxml` and `keyexpr_intersect.scxml` are
     uint32-equality placeholders. Nothing generates them into `out/`, and no Rust calls them.
     Wildcard matching exists twice, both written by hand: `wz_session_core::keyexpr_match`
     and the separate dynamic programs in `wz-zenoh-keyexpr`. So keyexpr matching is K, not
     A, and only if a bound on keyexpr length is declared.
  2. Not confirmed: whether one algorithm may call another that takes a `bytes` parameter.
  3. Not confirmed: whether `lookup` accepts a text key (row 48, encoding name to id).
  4. xxh3 (row 60) needs its 128-bit multiply decomposed by hand, and must stay bit-exact
     with upstream.
  5. Rows 25 and 80 are two implementations of the `_time` grammar.
  6. Rows 28 and 45 could instead be classed S.
