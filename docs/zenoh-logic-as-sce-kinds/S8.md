# Census slice S8: the zenoh-c preset's C ABI (wz-capi-c)

Scope: `crates/wz-capi-c/src/`, all 58 files (55,576 lines). Line counts are production lines:
the 12,823 lines of `#[cfg(test)]`-attributed `mod` blocks are removed (an awk pass that drops each
such block to its closing brace at column 0), which leaves 42,753 lines. They INCLUDE doc comments,
which are about half of most files, so read them as the size of a responsibility, not as code to
translate. Row lines are apportioned within a file by the items a row cites, so they are
approximate. `build.rs` (SONAME linking), `crates/wz-capi-c/examples/hold_a_listener.rs` and the C consumers under
`tests/` are outside `src/` and not counted: no protocol logic, they are a build helper, an example
and test programs.

What this crate is: the zenoh-c ABI over the session model `wz-capi-core`, which it shares with the
zenoh-pico ABI. The face registry, the declaration SSOT replayed per face, the fan of a get or a
put across faces, the matching aggregation, the cancellation model, the group aggregate and the
delivery lane are `wz-capi-core`'s (slice S7, per `docs/zenoh-logic-as-sce-kinds/crates.md`), and
under it the runtime (S4, S5) and `wz-session-core` (S1-S3). Those rows are cited, not
re-classified. What is classified here is what the C ABI itself decides: when a C closure's
`drop(context)` runs and so when a get, a scout or a channel is over; the order an entity is
retracted in; what a reply call admits; how a C config document is stored; which shared-memory
spelling selects which policy and when a buffer is writable; the zenoh-ext merge and cache built on
the C entry points; and the wz-own doors.

Every file has rows; none is left out. Observation-plane doors (`clock_source`, `event_log`,
`supervision`, `snapshot`) are X because what they do is `wz-capi-port`'s (S7). `identity.rs` is S
(key and certificate files). `config_verdict*.rs` is D.

Readings used throughout (owner and SCE session, 2026-11-19):

- U8 is withdrawn as a request: concurrency belongs in the seam through SCE `queue` / inbox doors
  (SCE ADR 0084). A lock or atomic that only guards protocol state is classified by the state (K or
  U1) plus an S door, and the note says so. No row here carries U8.
- U4 is answered by a boundary binding and U2 by a text-grammar codec; neither changes a row here,
  since this crate holds no codec step and its text grammars (`_anyke`, canon, the zid hex) are
  session-core's.
- Where a C semantic rides on Rust machinery (an `Arc` count as completion, a `Drop` as an
  undeclare, field or local drop order as an ordering rule), the note says "rides on Arc/Drop": a
  generated form needs it as an explicit event (leg ended, callback released, hold released).

SCE references (read from `origin/main` of the scxml-core-engine repository, `e7640cec`):

- `[cat:<kind>]` = the kind's entry in `sce-build/src/forge/kind_catalog.rs` (the source of
  `sce-codegen kinds`).
- `[cat:queue]` notes = the `queue` entry of that catalogue: "states how many producers and consumers, and the
  progress it must give"; "exactly one storage: bounded (a fixed capacity), segmented (grows from an
  allocator) or intrusive".
- `[F4.3]` = `SCE_FORGE.md` §4.3 lookup (enumerated input to output) and
  `docs/SCE_ACCEPTED_SUBSET.md:6201`: "a lookup keyed by a text, which no backend's table compares
  alike" is refused.
- `[F4.12R]` = `SCE_FORGE.md:2341`: a record's fields are fixed-width numbers, `bool`, `enum:` or a
  bounded `string`; "A `bytes` field is refused too".
- `[SUB-LV]` = `docs/SCE_ACCEPTED_SUBSET.md:5826` "List variables": append, clear, `len()`, index
  read, `<foreach>`; an element is never written.
- `[SUB-BC]` = `docs/SCE_ACCEPTED_SUBSET.md:8282ff`: "a `sce-static` statechart has no variable of
  that kind [bounded-collection]".
- `[SUB-ENC]` = `SCE_FORGE.md` §4.6.1 / §4.6.4: codec encodings are `cbor` and `content-line`.
- `[F-OVW]` = `SCE_FORGE.md:3193`, `:3201` (ADR 0062): `sce:on-full="overwrite-oldest"` on a
  `queue` "was ruled out before admission"; the `broadcast-log` admitted instead keeps every entry
  for every reader and offers `producers` `one` only.
- `[ADR84]` = SCE `docs/adr/0084-...one-inbox-and-one-processor-door.md`: D1 (`:124`) an engine is
  confined to its owner thread; D2 (`:146`) one inbox per session tree; `:412` "They are the only
  waits left; no input waits for a macrostep" (only `start`, `stop` and the destructor wait).

## Summary

- Lines by class (approx., doc comments included): A=0, K=10,624, G=3,438, S=2,766, D=1,294,
  X=24,631 (of 42,753). The C ABI holds no generated SCE code of its own; its generated parts are
  reached through the matcher (S2 row 1). X dominates: layouts, ownership exports and marshalled
  values. The K rows are the ABI's own decisions (completion, consumption on every path,
  retraction, admission, option folds); most of them lean on tables `wz-capi-core` holds (S7).
- Rows: 73.
- Gaps found:
  - U1 (3 rows: 47, 53, 61): the holder count per chunk, the protocol-keyed client storage, the
    instant-ordered merge.
  - U3 (3 rows: 31, 59, 61): reply, cached-sample and parked-sample records holding text, bytes and
    an attachment.
  - U10 (3 rows: 10, 31, 61): the serializer's growable buffer, the replies of one callback, the
    samples parked while a query is open.
  - U2b (2 rows: 11, 59): the config leaf store keyed by path, the publication cache keyed by key.
  - U12 (1 row: 11): a JSON5 document held, decomposed and rendered.
  - U5 (1 row: 11): the JSON5 value tree.
  - U17 (1 row: 38): a consumed queue that forgets its oldest element when full, with several
    producers. SCE ruled `sce:on-full="overwrite-oldest"` out of `queue` (a consumed queue whose
    full end the producer also writes loses the wait-free property), and the `broadcast-log`
    admitted instead is read without removal and offers one producer only `[F-OVW]`. zenoh-c's RING
    channel is exactly the refused shape: one consumer that removes, several face threads that
    produce, the oldest dropped.
  - U18 (1 row: 21): a post from a thread that is not the owner whose effects must have been
    applied before the posting call returns. zenoh-c runs a same-session delivery's callbacks
    inside `z_put` / `z_get` / a reply, on the calling thread, even while a face's drive runs
    (measured, R3069). `[ADR84]` makes every cross-thread input a post that returns at once ("no
    input waits for a macrostep"); only `start`, `stop` and the destructor wait. A generated
    session owned by a drive thread therefore cannot keep the contract unless a post can wait for
    its application, or the caller can become the owner for the delivery.
  - No row carries U8: the atomic interest counter (row 22), the channel lock (rows 37-38), the
    lazy provider's mutex and condvar (row 50) and the fetching lock (row 61) guard protocol state
    and are classified by that state, with an S door, per the withdrawn-U8 reading.
- Rows where a C semantic rides on Arc/Drop (a generated form needs the named event): 14
  (scout over), 16 and 30 (callback released, retraction order), 19 (last holder of a key
  declaration and an interest), 22 (listener retired with its publisher), 24 (token retracted on
  drop), 25 and 26 (get over when the last leg and the issuing guard let go; local and field drop
  order), 32 (Final on the last hold), 37 (disconnect on the closure's drop), 40 (cancel waits for
  dropped callbacks, in S7), 44 (unwatch), 47 (holder count as `Arc::strong_count`), 56 (entity
  retraction order), 60 (fetch ends on the reply closure's drop).
- Deliberate fixes to carry: rows 6, 10, 11, 12, 13, 16, 18, 19, 21, 24, 25, 26, 27, 28, 31, 32, 33,
  34, 37, 41, 44, 45, 47, 48, 49, 50, 55, 56, 57, 59, 61, 65.
- Doubts:
  - Row 44: with `history`, the listener reads the connected faces and then installs the watch
    (`events.rs:2013`, `:2025`). A face that comes up between the two reads is in neither, and one
    that goes down there is reported Up and never Down. Not checked against upstream's ordering.
  - Row 44: a background listener is leaked on purpose, and its `FaceSource` holds an
    `Arc<SharedSession>`, so the session's state stays allocated after `z_close` for as long as the
    process runs. Whether that is observable was not checked.
  - Row 37 is K only if the end of a FIFO (the producer's drop) is carried as an element of the
    queue; the `queue` kind states no close.
  - Rows 9 and 10 split one format: K for one fixed-width or zint value, G for the stream. A
    bounded profile would turn row 10 into a `[cat:codec]` over a declared maximum.
  - Row 21's lines are the decision only; the callbacks it governs are counted in rows 16, 26
    and 30.
  - The K rows that cite S7 are K for this ABI's part alone; S7 was not written when this slice was
    taken, so its rows are named by crate, not by number.
