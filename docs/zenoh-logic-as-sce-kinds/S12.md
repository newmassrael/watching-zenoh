# Census slice S12: application transport, stream supervision and key ids

Scope: files of `crates/wz-session-core/src/`, `crates/wz-runtime-tokio/src/`,
`crates/wz-runtime-coop/src/` and `crates/wz-capi-pico/src/` that no row of S1-S11 cites:
`app_link_table.rs`, `app_transport.rs`, `shared_key_ids.rs`, `stream_supervisor.rs`,
`zid_derivation.rs` and `handshake_stray.rs` of the session core; `app_link.rs` of each runtime;
and of the pico C ABI `app_transport.rs`, `stream_supervision.rs`, `key_ids.rs`, `e2e.rs`,
`e2e_receiver.rs`, `e2e_sender.rs`, `instance_key.rs`, `message_catalog.rs`, `replay_publisher.rs`,
`replay_subscriber.rs`, `redeclare.rs`, `option_fields.rs`, `os/arith.rs`,
`os/zephyr_arith.rs`, `ext_interface.rs` (row 44, the interface the doors above reach the
core through, written after the slice) and `additional.rs` (row 48, the interface version the doors
need, written after it). Each was checked uncited by searching `docs/zenoh-logic-as-sce-kinds/S*.md`
for its path and its basename: no row of S1-S11 cites any of them (S11 names the pico doors and
`stream_supervisor.rs` only to leave them to this slice), and S7 row 68 says "the Unix,
Windows and Zephyr backends with their arithmetic" in its text and cites neither `os/arith.rs` nor
`os/zephyr_arith.rs`, so both are classified here (row 43). Every file of the scope has a row; no
file is left out, and every crate of the scope has rows. Several of these files were written in the
last two days for an application-layer proof of concept and are classified as they stand on this
tree (`4481c5ac8`).

The library logic behind the pico doors for end-to-end protection, instance keys, the message
catalogue and the replay cache (`crates/wz-app-frame/` `e2e_*`, `instance_key`, `message_catalog`,
`replay_*`, and `crates/wz-session-core/src/replay_*.rs`) is S11's and is not classified here; a
door row says "S11" where it calls into it and keeps to what the door itself decides. The segment
writer the replay doors use is S10 rows 8-9.

Line counts are production lines: each file from its first line to the line before its first
`#[cfg(test)]` module (every test module of these files runs to the end of the file, checked by
listing the top-level items after it), comments, doc comments and blank lines KEPT. Where one file
holds several rows it was cut at item boundaries and the split is approximate; the rows of each
file sum to its count. The Rust total is 10,457 lines (session core 2,594, the two runtimes 1,355,
the pico ABI 6,508). The two A rows count the SCXML documents they run (`sources/session/app_link.scxml`
104, `sources/session/stream_activation.scxml` 81), which are outside that total;
`sources/algorithms/stream_deadline.scxml`, which `stream_supervisor.rs` also calls, is S11 row 37.
S11's scope paragraph names this slice's pico doors and `stream_supervisor.rs` as reached through
and not classified there.

**Which pico rows are on the path the C build reaches first.** That path is the cooperative engine
(`engine-coop` on a host, `os-zephyr` in a Zephyr image; S7's header). Every door of this slice but
two belongs to a capability that selects `std` (`app-transport`, `e2e-supervision`, `e2e-sender`,
`e2e-receiver`, `instance-key`, `message-catalog`, `replay-cache`, `shared-key-ids` through
`unstable-api`; `crates/wz-capi-pico/Cargo.toml:303-405`), and a build that names `os-zephyr` with a
capability that selects `std` is refused (`crates/wz-capi-pico/src/lib.rs:113`). Each pico row's
note therefore starts with its path: **coop host** (a host build of `engine-coop` carries it, and
the tokio engine's build too), **image** (an `os-zephyr` image carries it as well), or **Windows**.
None of the doors touches an engine but `app_transport.rs` (the links of either engine),
`key_ids.rs` (the open) and `redeclare.rs` (the session).

SCE references (read from `origin/main` of the scxml-core-engine repository, `4d3c9309e02`; the wz
pin `vendor/sce` is `9ae6a6b6`). The keys of S5, S7 and S10 are reused with their meaning, at the
lines `origin/main` now has them:

- `[cat:<kind>]` = the `KindGuide` of that kind in `sce-build/src/forge/kind_catalog.rs` (S7).
- `[F4.3]` = `SCE_FORGE.md` §4.3 lookup: keys are numeric or `enum:<alias>`, no text key.
- `[F4.12B]` = `SCE_FORGE.md` §4.12 "Byte-buffer-build" (line 2230): an algorithm builds and
  returns a `bytes` value of a stated bound.
- `[SUB-LV]` = `docs/SCE_ACCEPTED_SUBSET.md` line 5892: a `sce-static` list element "is read and
  never written".
- `[SUB-BC]` = `docs/SCE_ACCEPTED_SUBSET.md` line 8310: "a `sce-static` statechart has no variable
  of [bounded-collection] kind".
- `[SUB-BYTES]` = `docs/SCE_ACCEPTED_SUBSET.md` line 5328: a `bytes` variable declares the most
  bytes it holds, and "a byte string with no bound is refused where it is declared".
- `[SUB-MAP]` = `docs/SCE_ACCEPTED_SUBSET.md` line 5999ff and ADR 0108: `map<K, T>[N]` /
  `set<K>[N]`; a key is a fixed-width integer, `bool`, enum, bounded text, bounded byte string or a
  record of keys; "a value read here is a number, a `bool`, an enum, a text, a byte string or a
  record" (so a map holds no machine instance); "a limit the machine reads at run time is the
  document's own variable, tested before the put". "The Interpreter and Rust run a map; no other
  backend generates one yet" (ADR 0108 steps 1-5 landed; C11, step 6, and algorithm slots, step 7,
  have not), and the wz pin predates it. Rows it would answer stay G and say so.
- `[ADR0084]` = SCE ADR 0084: what reaches an engine from outside enters through one inbox and one
  processor door.

Two catalogue readings of 2026-11-19 are applied as the brief states them. **U8 is withdrawn as a
request**: the locks of this slice (the transport's table lock, each door's `Mutex`) guard state
that is classified by what it is, and the lock is the seam's door (S, `[ADR0084]`); rows 2, 7,
18, 26, 32 and 40 say so. **U4 is answered by a boundary binding**; no row here decodes a codec value
and branches on it.

Where a C semantic rides on Rust machinery (an `Arc` count as the end of an object's life, `Drop`
as a release or a query's end), the note says **Drop:** and names the site; each is a place the
target structure needs an explicit event.
