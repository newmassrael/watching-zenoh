# Census slice S10: application framing, bridges, and files the first census missed

Scope: the whole `src/` of `crates/wz-app-frame/`, `crates/wz-rest/`, `crates/wz-mesh-client/`,
`crates/wz-switchboard-codegen/`, `crates/wz-switchboard-schema/`, `crates/wz-plugin-abi/`,
`crates/wz-volume-abi/`, `crates/wz-ap-demo/` (with its `build.rs`), `crates/wz-ap-demo-app/` and
`crates/wz-workload/`; and the production files of `crates/wz-session-core/`,
`crates/wz-runtime-tokio/`, `crates/wz-session-mcu/`, `crates/wz-runtime-coop/` and
`crates/wz-ext-pubsub/` that no row of S1-S6 cites (section "Files the first census missed").
`crates/wz-app-frame/` is classified as it stands on this tree; the code a peer branch is moving
into it (`proto_lex` / `proto_parse` / `proto_schema` from `wz-capture`, instance key, message
catalogue, e2e receiver and sender) is not here and is not classified.

Left out, each for a stated reason: `crates/wz-runtime-tokio/src/built_fixture.rs` (compiled only
under `cfg(all(test, ...))`, `lib.rs:443`); `crates/wz-ext-pubsub/src/advanced_subscriber/host/`,
`plans/` and `state/` (each holds only `tests.rs`; the production files beside them are S6 rows
83-86's); `crates/wz-ap-demo/tests/`; the `#[cfg(all(test, ...))]` constants of
`crates/wz-ap-demo/src/args.rs:3626-4433` (`ARGV_ONLY_KIND_LEDGER`, a test ledger); the generated
`out/wz-ap-demo-app/*.rs` (982 lines, generated, not hand-written) and the three SCXML sources of
`crates/wz-ap-demo-app/sources/` (85 lines, documents, not Rust). Every crate of the scope has rows;
none is excluded whole.

Line counts are production lines: whole files with `#[cfg(test)]` / `#[cfg(all(test, ...))]`
modules removed, comments and doc comments INCLUDED (doc comments are 40-70 % of most of these
files, so a count is the size of a responsibility, not the code to translate). Where one file
holds several rows the file's count is split by item ranges and the split is approximate. Counted
by a line scanner over each file, checked by hand where a test module's text holds a `}` at
column 0 (`wz-switchboard-codegen`, `wz-ap-demo/src/args.rs`).

SCE references (read from `origin/main` of the scxml-core-engine repository, `e7640cec`; the wz
pin `vendor/sce` is `9ae6a6b6`, an ancestor). The S5 keys `[cat:<kind>]`, `[F4.3]`, `[F4.12L]`,
`[SUB-LV]`, `[SUB-BC]`, `[SUB-TT]`, `[SUB-ENC]` and `[RFC5I]` are reused with S5's meaning
(`[SUB-BC]` now at `docs/SCE_ACCEPTED_SUBSET.md` line 8282ff, `[SUB-ENC]` at line 4701ff,
`[SUB-TT]` at line 785ff). New keys:

- `[ALG-CRC]` = `tests/forge/resources/algorithm_crc16.scxml` and `algorithm_crc16_table.scxml`
  with `SCE_FORGE.md` line 395 and 417: a CRC is an algorithm over a `bytes` parameter, its table
  a build-time `<sce:const>` fold, and "bitwise operations and shifts ... wrap at their width,
  which is what a CRC table's shifted-out bits rely on".
- `[F3.4]` = `SCE_FORGE.md` §3.4 expression grammar: calls are to declared functions; `round(x)`
  and `floor(x)` are named; no logarithm or exponential is named anywhere in `SCE_FORGE.md`.
- `[SUB-MAP]` = `docs/SCE_ACCEPTED_SUBSET.md` line 5973ff "Map and set variables" and ADR 0108:
  `map<K, T>[N]` / `set<K>[N]` in a `sce-static` statechart, keys of a fixed-width integer, enum,
  bounded text, bounded bytes or a record of keys. Landed 2026-11-19 for the Interpreter and Rust
  (ADR 0108 "Order of work" steps 1-5); C11 (step 6) and algorithm slots (step 7) are not landed,
  and the wz pin `9ae6a6b6` predates all of it. U1 and U2b rows below stay G for that reason;
  each says where `[SUB-MAP]` would answer it.
- `[ADR0084]` = SCE ADR 0084: what reaches an engine from outside enters through one inbox and one
  processor door. Under the 2026-11-19 reading (brief), a lock, channel or thread that only carries
  commands to one owner is S (the door), and the state behind it is classified by what it is.
- `[ADR0102]` = SCE ADR 0102: a mapped message type names its codec binding. The 2026-11-19
  reading of U4 (a boundary binding: door bytes -> a bound codec -> a typed schema event; a
  `<send>` of a bound schema -> the encoder) is an owner/SCE-session decision not yet written in
  SCE's text; no `origin/main` document says "boundary binding" or "text-grammar codec". U4 and U2
  are used below with that reading noted where it matters.

wz's switchboard (`wz-switchboard-schema`, `wz-switchboard-codegen`, `wz_session_core::switchboard`,
S3 rows 34-35) is wz's own form of the boundary binding the U4 reading names: a keyexpr row binds a
domain event, a `codec` on the row decodes the sample payload into the event's typed `_event.data`.

- U15, what it is: a layout known only at run time. `wz-app-frame` takes the header of an end-to-end
    protection frame or of an application's split message as a PROFILE the caller passes on every
    call (field widths, byte order, XOR masks, bit splits, `equals` marks, the CRC model and its
    cover order), so a deployment's constants never enter this public repository
    (`e2e_profile.rs:18`). `[cat:codec]` fixes "each field's byte offset, bit size and byte order"
    in the document at build time; nothing in SCE interprets a layout description at run time.
    Two ways to close it, which are the owner's decision and not this census's: (a) a deployment
    writes its profile as a codec document in its own repository and generates from it, and rows
    3-5 and 9 become K (codec with ADR 0095 bit fields, an algorithm for the cover order) while the
    doors that take profile text at run time change contract; (b) SCE gains a kind whose input is
    a layout description. Rows 1, 2, 6 and 8, the mechanism around the layout, are K either way.
