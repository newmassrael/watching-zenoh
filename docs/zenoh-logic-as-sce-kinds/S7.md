# Census slice S7: the zenoh-pico preset's C ABI on the cooperative engine

Scope: `crates/wz-capi-coop/src/`, `crates/wz-capi-pico/src/`, `crates/wz-capi-port/src/`,
`crates/wz-capi-core/src/`. Test-only files skipped (`wz-capi-coop/src/tests.rs`,
`wz-capi-coop/src/tests/`, `wz-capi-coop/src/scout/tests.rs`,
`wz-capi-core/src/drive/router_node/engine/port_tests.rs`). Line counts are production lines: every
item under `#[cfg(test)]` (inline `mod` blocks and single test-only functions) removed by brace
matching, comments and doc comments KEPT, blank lines kept. Doc comments are 40-60 % of most files
here, so read a count as the size of a responsibility, not as code to translate. Where one file
holds several rows, the file was cut at item boundaries and each range counted the same way;
sums per file match the file's count within a few lines. Totals: wz-capi-coop 5,937,
wz-capi-port 2,875, wz-capi-pico 30,020, wz-capi-core 20,381 (59,213).

Each crate in scope has rows. Two placements matter for reading the totals:

- **What the C build reaches first** is wz-capi-pico over wz-capi-port over wz-capi-coop (the
  features `engine-coop` and `os-zephyr`, `crates/wz-capi-pico/Cargo.toml`). Rows 1-68 are that
  path.
- **wz-capi-core is the tokio engine** (`engine-tokio`, the pico crate's default, and the engine
  of the zenoh-c ABI, which is not in this slice). It is not on the cooperative path; rows 69-106
  classify it because it is in scope, and it is reported apart in the Summary.
- **The TX lend book is not in these crates.** `TxStore`/`TxLender` are
  `crates/wz-runtime-coop/src/link_storage.rs` (S5 row C6, main doc section 7 W4); the
  cooperative engine reaches it through the links `wz-runtime-coop` and `wz-runtime-zephyr` hand
  it, and no file of the four crates lends, books or returns a transmit slot (searched for
  `link_storage`, `TxLender`, `TxStore`, `lend`). It gets no row here.

SCE references (read from `origin/main` of the scxml-core-engine repository, `e7640cec`):

- `[cat:<kind>]` = the `KindGuide` of that kind in `sce-build/src/forge/kind_catalog.rs`, the text
  `sce-codegen kinds` emits. `[cat:queue]`: "exactly one storage: bounded (a fixed capacity),
  segmented (grows from an allocator) or intrusive", "a queue only ever gives back the oldest
  element". `[cat:bounded-collection]`: "a typed container whose capacity is fixed when the
  program is built".
- `[F4.3]` = `SCE_FORGE.md` §4.3 lookup: keys are numeric or `enum:<alias>`, no text key (S5).
- `[F4.12]` = `SCE_FORGE.md` §4.12 records: a record's string has one write and one comparison;
  a `bytes` field is refused (main doc section 2).
- `[SUB-LV]` = `docs/SCE_ACCEPTED_SUBSET.md` line 5866ff: a `sce-static` list element "is read and
  never written", whole-list assignment refused; no keyed update or remove.
- `[SUB-BC]` = `docs/SCE_ACCEPTED_SUBSET.md` line 8281ff: "a `sce-static` statechart has no
  variable of [bounded-collection] kind".
- `[SUB-TT]` = `docs/SCE_ACCEPTED_SUBSET.md` line 768ff: text-template holes are `string[B]`,
  fixed-width integer or closed enum; a list or record hole is refused.
- `[SUB-ENC]` = `docs/SCE_ACCEPTED_SUBSET.md`: codec `sce:encoding` is `cbor` or `content-line`
  (S5).
- `[ADR0084]` = `docs/adr/0084-what-reaches-an-engine-from-outside-enters-through-one-inbox-and-one-processor-door.md`:
  an input from a thread that finds another one running the engine's macrosteps is posted to the
  session's inbox and applied at the next macrostep boundary.

Two catalogue readings of 2026-11-19 are applied as the brief states them. **U8 is withdrawn as
a request**: a lock or atomic that only guards protocol state is classified by what the state is,
and the lock is the seam's door (`queue`/inbox, `[ADR0084]`); rows 6, 13 and 83 say so. **U4 is
answered by a boundary binding**: a step that builds a Push or a Request is a `<send>` of a bound
schema, so no row here carries U4.

A column the brief asks for in the notes: where a C semantic rides on Rust machinery (an `Arc`
refcount as completion, `Drop` or field order as undeclare order), the note says **Drop:** and
names the site. Each is a place the target structure needs an explicit event.
