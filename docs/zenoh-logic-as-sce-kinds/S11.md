# Census slice S11: the application frame layer and its replay

Scope: the files `crates/wz-app-frame/src/` gained after S10 was taken (`e2e_receiver.rs`,
`e2e_stream_sender.rs`, `instance_key.rs`, `message_catalog.rs`, `message_catalog_table.rs`,
`proto_lex.rs`, `proto_parse.rs`, `proto_schema.rs`, `proto_decode.rs`, `segment_chain.rs`,
`replay_admission.rs`, `replay_pieces.rs`); `crates/wz-session-core/src/replay_publisher.rs` and
`replay_subscriber.rs`; and the eight SCE documents written for them or beside them
(`sources/algorithms/{stream_deadline,declaration_stall_deadline,drop_report_due,e2e_counter_step,e2e_counter_verdict,replay_reply_admission}.scxml`,
`sources/session/{replay_round,replay_serving}.scxml`). Read on `w-divergences` at `4481c5ac8`.

Already classified elsewhere and not redone: `e2e_crc`, `e2e_judge`, `e2e_profile`, `e2e_frame`,
`segment_profile`, `segment_sender` (S10 rows 1-9); `crates/wz-app-frame/src/lib.rs` (S10 row 10).
`lib.rs` is now 110 lines where S10 counted 60; the 50 added lines are the module table of its
`//!`, the `cfg(feature = ...)` lines of the new modules (`replay`, `proto`, `instance-key`) and an
`extern crate self` for the catalog tests. They bring no decision, so S10 row 10 holds the file and
there is no row for it here. `replay_cursor.rs` and `replay_pacing.rs` are S3 row 50's (the
declaration replay cursor; the brief's "S3 row 84" is that row). Reached through, not classified
(S12's): the C doors of `crates/wz-capi-pico/src/` (`e2e.rs`, `e2e_receiver.rs`, `instance_key.rs`,
`message_catalog.rs`, `replay_publisher.rs`, `replay_subscriber.rs`), which are the production
callers of every Rust type in this slice, and `crates/wz-session-core/src/stream_supervisor.rs`,
which calls `stream_deadline` (row 37).

The analyzer is outside the census. `proto_lex`, `proto_parse`, `proto_schema`, `proto_decode` and
the joining state of `segment_chain` moved here from `crates/wz-capture/`. What is left there:
`crates/wz-capture/src/proto_schema.rs` (235 lines) re-exports `wz_app_frame::proto_schema` at its
old paths and adds the analyzer's declaration text (`#@file=...`, `K=protobuf@pkg.Msg`, `K:3.2=name`
lines) written from the linked tree; `crates/wz-capture/src/segment_chain.rs` (189 lines) is
`pub use wz_app_frame::segment_chain::*` plus the field walker's `JudgedSegments`, `Frontier` and
`PieceLedger` (`dissect` feature). `proto_lex`, `proto_parse` and `proto_decode` have no file left
there. None of it is classified.

Every crate of the scope has rows; no file of the scope list is left out.

Line counts are production lines: whole files with the trailing `#[cfg(test)] mod tests` removed
(`proto_lex.rs` from line 718, `proto_parse.rs` from 1526, `replay_admission.rs` from 105,
`replay_pieces.rs` from 125, `replay_publisher.rs` from 606, `replay_subscriber.rs` from 603; the
`#[cfg(test)]` constant at `instance_key.rs:508` is two lines), comments and doc comments INCLUDED,
as S10 counts. The test-only files beside them (`e2e_rules_tests.rs`, `instance_key_tests.rs`,
`message_catalog_tests.rs`) are not production and not counted. Where one file holds several rows
its count is split by item ranges; the split is approximate and each file's rows sum to the file.
An A row gives the SCE document's own line count, not Rust lines.

SCE references (read from `origin/main` of the scxml-core-engine repository, `4d3c9309e02`; the wz
pin `vendor/sce` is `9ae6a6b6`). The S5 and S10 keys `[cat:<kind>]`, `[F4.3]` (now `SCE_FORGE.md`
line 684), `[SUB-ENC]`, `[SUB-TT]`, `[SUB-BC]` and `[ADR0084]` are reused with their meaning, and:

- `[SUB-MAP]` = `docs/SCE_ACCEPTED_SUBSET.md` line 5999ff "Map and set variables": `map<K, T>[N]`
  with a key of a fixed-width integer, `bool`, enum, bounded text, bounded byte string or a record
  of keys, and a value that is a number, `bool`, enum, text, byte string or record; "a map held
  inside another type (a list's element, an optional value)" is refused. Line 6015: "The
  Interpreter and Rust run a map; no other backend generates one yet". ADR 0108 step 6 (C11) and
  step 7 (algorithm slots) are not landed and the wz pin predates all of it, so U1 and U2b rows
  stay G; each says where `[SUB-MAP]` would answer it on the Rust lane.
- `[SUB-LV]` = `docs/SCE_ACCEPTED_SUBSET.md` line 5852ff "List variables": a statechart
  `list<T>` holds fixed-width numbers or `bool`, with a build-time `sce:capacity`; append and
  clear only.
- `[SUB-BYTES]` = `docs/SCE_ACCEPTED_SUBSET.md` line 5328ff "A byte string": a `bytes` variable
  declares its bound with `sce:capacity`, a record's `bytes` field with its schema's
  `sce:max-size`; "a byte string with no bound is refused where it is declared".
- `[F-BL]` = `SCE_FORGE.md` line 3193ff, the admission of `broadcast-log`: a ring one producer
  appends to and readers read by their own cursors, forgetting its oldest; "Element type, producer
  cardinality, retention, stamp width and required progress are build-time; only `head` and the
  slot contents are runtime"; an `overwrite-oldest` flag on `queue` "was ruled out", because "a
  queue consumes ... and a full queue refuses the writer".

U15 is used below for a protobuf schema handed over at run time as well as for S10's header
profile: in both the payload's layout is data the caller passes, and the same two ways close it
(the deployment generates from its schema at build time, or SCE reads a layout description). U12
and U2a/U2b keep the 2026-11-19 readings (U2 by a text-grammar codec; U4 by a boundary binding);
no row here needs U4. U8 is not used: nothing in the scope takes a lock or an atomic (every type
is `&mut self`, sans-I/O; the C doors that share them are S12's).
